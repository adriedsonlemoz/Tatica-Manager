Versão inicial consolidada


ATUALIZAÇÃO DO RENDERER ANDROID — 0.1.1.110

No Android, o SurfaceView do libGDX deve permanecer estritamente contido no retângulo do campo definido pelo Flutter. A integração usa Hybrid Composition real, tamanho 105/68 explícito no widget, host nativo com clipping/MATCH_PARENT e FitViewport 1050x680 no renderer. Não substituir isso por composição por textura enquanto o GLSurfaceView for adicionado pelo Fragment após a criação do PlatformView. Nomes, jogadores, bola, gols e demais refinamentos pertencem somente à camada visual; Match Engine e coordenadas permanecem em Dart.


ATUALIZAÇÃO ARQUITETURAL — 0.1.1.107

A partir da 0.1.1.107, o Android pode usar libGDX exclusivamente como renderer visual do campo da partida. O Match Engine permanece integralmente em Dart e continua sendo a única fonte de regras, resultados, eventos e coordenadas. Flame permanece como fallback visual e nenhuma lógica de partida deve ser duplicada no renderer nativo. Esta atualização substitui somente a escolha original de Flame como renderer obrigatório do campo; as demais restrições arquiteturais continuam válidas.

CONTEXTO

Quero criar uma nova versão do Tática Manager do zero, usando Flutter + Dart.

O projeto antigo está anexado e deve ser utilizado como referência funcional, principalmente para regras, fórmulas, estruturas de dados, simulador, IA, mercado, finanças, jogadores, calendário e testes.

O projeto antigo NÃO deve ser simplesmente convertido de React para Flutter.

Quero uma nova base limpa, moderna, mobile-first e realmente pensada como um jogo para Android e iOS.

Também existe uma imagem conceito anexada da interface. Essa imagem deve ser tratada como REFERÊNCIA VISUAL PRINCIPAL E OBRIGATÓRIA da nova versão.

======================================================================
ATUALIZAÇÃO ARQUITETURAL — 0.1.1.75 — CARREGAMENTO DE LIGAS POR SAVE
======================================================================

A base continua com uma única liga real cadastrada, mas a criação de carreira agora persiste `CareerLeagueSetup` no schema 12 para preparar a expansão sem obrigar todo o catálogo futuro a entrar em todo save.

Regras atuais:
- usar somente competições reais de `CompetitionCatalog`; não criar ligas fictícias para demonstrar o sistema;
- a competição do clube do usuário é sempre completa;
- ligas `unloaded` permanecem no banco/catálogo instalado, mas seus clubes não são materializados na nova carreira;
- ligas `background` ficam preparadas para mercado/contratos e resolução estatística de jogos CPU;
- ligas `full` continuam usando o Match Engine existente;
- Flame continua somente como representação visual;
- não habilitar alteração de ligas após o início da carreira sem política explícita de reconstrução de calendário, classificação, resultados e estatísticas;
- SQLite v3 preserva o payload integral e usa resumo leve para listar saves sem desserializá-los por completo.

Consultar `docs/LEAGUE_LOADING.md` antes de expandir países/divisões ou alterar este fluxo.


============================================================
ATUALIZAÇÃO DA ARQUITETURA — 0.1.1.76
============================================================

O trecho inicial deste documento descreve o escopo histórico da primeira versão. A base atual já evoluiu para suportar expansão futura de competições.

Preservar a fundação multi-competição existente:
- `CareerLeagueSetup` define full/background/unloaded por save;
- `CompetitionSeasonState` mantém progresso, classificação, estatísticas e disciplina por `competitionId`;
- `CareerState.fixtures` é o calendário global usado para conciliar torneios simultâneos;
- o mesmo clube/jogador pode participar de várias competições sem duplicação de elenco;
- `MatchEngine` continua único e não conhece tabela/persistência;
- Flame continua somente visual;
- formatos de copa só devem ser ativados quando seu regulamento real for implementado;
- competições internacionais futuras não devem ser forçadas para dentro de um país no catálogo;
- preservar saves, IDs persistentes e migrações.

A expansão planejada pode começar pela Série B e depois estaduais. Não adicionar ligas fictícias apenas para demonstrar a arquitetura.
